# 每日推荐刷新策略（v1.7.1）

首页每轮成功推荐固定为 20 首，网格始终保持 5 列，共 4 行。

优先请求 `/everyday/recommend`，新候选不足时依次请求 `/recommend/songs`、`/top/card`（1–4）、`/top/song`、`/top/tag/card/youth` 和 `/top/card/youth`（3001、3005）。时间戳用于绕过 API 代理缓存，不代表上游强制更新参数。

`recommendationStrategy.js` 按标准化 hash 去重并过滤 localStorage 中当前账号/设备的展示历史。`recommendations.js` 的歌曲元数据归一化用于统一不同来源的歌曲名称、封面、歌手和时长。首页只使用严格的新歌筛选，不使用旧的旋转兜底策略。

仅在凑齐 20 首未展示歌曲时更新列表、保存历史；不足 20 首则提示候选不足并保留旧列表。上游候选有限，因此不能保证无限次成功刷新。历史默认保存最近 2000 首；清理浏览器存储、更换账号/设备或超过保存窗口后可能再次出现旧歌曲。

## 验证

迁移至 D 盘项目后的真实 API 连续 12 轮测试：每轮 20 首，累计 240 个不同 hash，跨轮重复为 0。合并远端兼容性修复后，30 项单元测试通过，生产构建通过。未将真实登录凭据或推荐歌曲数据提交到仓库。
